# Frontend Architecture: Current State

**Status:** Authoritative handover baseline, 2026-09-08
**Repository:** `Jackson-NSANZIMANA/e-recruitment-ui`
**Backend contract baseline:** `Jackson-NSANZIMANA/e-recruitment` at `47d9ad3ab019f6d2f826cfae2136cbff898d733f`

This document replaces the previous version of `frontend-architecture.md`. The previous document was useful as a historical correction record, but its direct-to-microservices and four-BFF topology became stale when ADR-021 introduced the single edge contract. Do not use the old claims as implementation guidance.

## 1. System boundary

The browser is designed to call **one edge origin** under `/edge/v1/**`. It does not call backend microservice ports directly and it does not send an `Authorization` header.

The authoritative contract is split deliberately:

- Backend: `docs/architecture/adr/ADR-021-edge-tier.md` and `services/edge-gateway/openapi/edge-v1.yaml`.
- Frontend: `packages/api-client/src/paths.ts`, `packages/api-client/src/transport.ts`, and `packages/auth/src/edge-client.ts`.
- Domain route and schema truth: `packages/contracts` in this repository, verified against the pinned backend commit.

The frontend is **edge-contract ready**, not edge-deployment complete. The backend repository currently contains the edge OpenAPI contract under `services/edge-gateway/openapi`, but no runnable edge service package or entrypoint was found in the current `main` tree. Until that composition exists and is proven, browser flows that require the edge are not production-ready.

## 2. Credential boundary

The browser receives only the edge session view. The officer JWT and applicant session token remain server-side behind the edge. The session cookie is `httpOnly`; the readable CSRF cookie is not a credential and is echoed in `x-csrf-token` for unsafe requests.

The frontend enforces this shape in code:

- `AuthProvider` probes `GET /edge/v1/session`; it never reads or decodes a browser credential.
- `createEdgeAuthClient` sends `credentials: 'include'` and no `Authorization` header.
- `createApiClient` invokes an operation id from `EDGE_OPERATIONS`, not a caller-supplied URL.
- Retry behavior comes from the operation registry. State-changing writes are not retryable.

Route guards are routing and presentation only. Agency isolation is enforced by backend authorization and PostgreSQL RLS, not by a React guard.

## 3. Frontend structure

There are two host applications:

- `apps/applicant-portal`
- `apps/officer-console`

The domain is split into six feature packages under `packages/features/*`:

- `identity`
- `applications`
- `adjudication`
- `scheduling`
- `field-ops`
- `compliance`

Feature packages expose a single public barrel and keep model, API, UI, route, and locale concerns together. Cross-feature imports are not allowed. `@usrp/contracts` is the only frontend domain contract source; `@usrp/shared-types` is not a replacement for it.

At this handover point the host apps still own their inline route tables in `apps/*/src/app.tsx`. The six feature route surfaces are not yet mounted into those routers. That work is intentionally gated behind a green install and verification path, not hidden behind fictional E2E coverage.

The design system boundary is Atlassian ADS with compiled extraction. Raw colour literals, domain vocabulary in the design-system layer, and undersized interactive targets are hygiene violations.

## 4. Build and verification contract

The same repository-owned checks must run locally and in CI:

```bash
pnpm install
pnpm verify
pnpm build
pnpm verify:extraction
pnpm security:scan
```

The frontend workspace must include `apps/*`, `packages/*`, `packages/features/*`, and `tooling/*`. Any new package depth requires a matching workspace glob and a regenerated lockfile. `pnpm-lock.yaml` is generated output and must never be hand-edited.

The current CI order is deliberate:

1. dependency-free hygiene tests and static gates;
2. install from the committed lockfile;
3. typecheck, ADS conformance, contract drift, tests, accessibility, build, E2E, and security;
4. one `Quality Gate` job that fails if any required job is not successful.

A red gate is not a waiver. `Quality Gate` must be configured as a required branch-protection check on `main` before feature work is merged.

## 5. Known blockers and non-negotiable follow-up

- The lockfile must be regenerated by running `pnpm install` on a machine with registry access, then committed. Do not synthesize or hand-edit it.
- The actual `pnpm install` error must be reproduced from the current remote branch, not an old local checkout. The current branch contains the nested feature-package workspace glob and the six package manifests; if a local checkout still reports `@usrp/feature-adjudication` as absent, fetch and switch to the current branch before changing manifests.
- `tooling/edge-dev` is a contract/proof harness, not the production edge. Its existence must not be reported as a deployed gateway.
- The frontend security scan remains staged until its first real-tree finding is read and either fixed or explicitly allowlisted with a reason.
- Feature-slice mounting comes after install and verification are green. Otherwise the gate cannot evaluate the code being mounted.

## 6. Superseded claims

The following claims from the previous document are retired:

- "There is no BFF" as the current topology. The correct current statement is: one edge tier is the browser boundary, and its backend runtime is still incomplete.
- "The browser reaches backend services directly" as frontend architecture. The browser contract is `/edge/v1/**`.
- Four per-agency BFFs and a `superadmin-bff`. ADR-021 rejects that topology in favor of one edge contract with agency derived from the server-side session.
- Ports 4021-4024 are reserved for nothing. The backend configuration and `edge-contract.md` name the edge deployment ports, even though the runtime composition is not complete.

When this document conflicts with an older architecture section, use the current edge contract, ADR-021, `packages/api-client/src/paths.ts`, and executable verification over prose.
