# Frontend handover closure: 2026-09-08

The integration train is now on `main`: CI hardening, the contract layer, the real edge transport, and the feature-slice proof harness have landed. The lockfile conflict was resolved by regenerating it with pnpm after merging `main`; it must never be hand-edited.

## Registry correction

Edge-owned operations now declare `upstreamOperationId: null` instead of impersonating `officerLogin`. That closes the old false-green mapping for `officerLogout`, `readSession`, and `refreshSession`. Every operation that fronts a backend route keeps an explicit contract operation ID, and the API client selfcheck fails on duplicate IDs, templated paths, or a renewed placeholder mapping.

## E2E correction

The legacy applicant journey used fictional `/api/*` endpoints and asserted a flow the backend cannot serve from a browser. It is now quarantined as an explicit `test.fixme` checkpoint. The next valid citizen E2E must target the edge OTP operations. NID verification, document upload, and application submission remain blocked until the backend edge gateway brokers the service-internal operations `verifyIdentity`, `uploadDocument`, and `submitApplication`.

## Build transition

The handover is closed. New work starts from verified edge operations and contract-generated types only. No new URL strings, generic status PATCH, browser system-token route, or invented domain enum may enter the frontend.
